# Freelance Portfolio Website

A responsive personal portfolio for a freelance web developer and graphic designer. Built with plain HTML, CSS and JavaScript.

## Files

- `index.html` — page content and sections
- `style.css` — responsive layout and visual styling
- `script.js` — mobile navigation, package selection and contact form behavior

## Before publishing

1. Open `index.html` and replace every instance of `Your Name` / `YourName` with your real name or preferred personal brand.
2. In `index.html`, replace `hello@example.com` with your real email address in the contact details.
3. In `script.js`, change `BUSINESS_EMAIL` from `hello@example.com` to the same real email address.
4. Replace the LinkedIn, GitHub and Instagram profile links with your actual profile URLs. Remove any social link you do not use.
5. Replace the three concept projects with real projects as you complete them. Until then, keep the note that they are illustrative concepts.
6. Review the package prices, deliverables, location and availability statement so they accurately reflect your offer.

## Run locally

No build tools or installation are required.

- Extract the ZIP file.
- Open `index.html` in a browser.
- For a smoother development workflow, open the folder in Visual Studio Code and use the Live Server extension.

## Publish free with Netlify

1. Create an account at https://www.netlify.com/.
2. Sign in and open the Netlify dashboard.
3. Choose **Add new site** / **Deploy manually** (the wording may vary).
4. Drag the extracted `freelance-portfolio` folder into the deployment area.
5. Wait for deployment. Netlify will provide a public website URL.
6. Open the URL on a phone and a computer to test the layout and links.
7. You can change the site name in the Netlify site settings. A custom domain is optional and usually costs extra.

## Publish with GitHub Pages

1. Create a GitHub repository and upload `index.html`, `style.css` and `script.js` to the repository root.
2. Open the repository's **Settings** → **Pages**.
3. Under the build/deployment source, select **Deploy from a branch**.
4. Select the `main` branch and `/ (root)`, then save.
5. Wait for GitHub Pages to publish and use the URL shown in the Pages settings.

## Contact form limitation

The included form uses a `mailto:` link. It validates the required fields and prepares an email in the visitor's default email app; the visitor must press Send. It does **not** send messages silently or store submissions on a server. For a form that submits directly from the website, connect a form backend such as Formspree or build a server-side endpoint. Never put private API keys in front-end JavaScript.
